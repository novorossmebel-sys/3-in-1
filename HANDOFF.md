# HANDOFF — СРЕДА · Калькуляторы (3 в 1)

Документ передачи: цели, результат, обнаруженные проблемы и способы их решения,
проверка и известные ограничения. Репозиторий: `novorossmebel-sys/3-in-1`,
рабочая ветка `claude/magical-noether-9ekvhi`.

---

## 1. Цели (что просил заказчик)

По сообщениям заказчика в ходе работы:

1. **Объединить три HTML-калькулятора в один** с вкладками:
   - «Просчёт мебели» (себестоимость изделия + КП),
   - «Фасады» (МДФ / шпон + бланк заказа + договор),
   - «Распил» (раскрой, кромление, присадка, пазование).
2. **Доступ с любого компьютера по паролю** — открываю файл, выбираю вкладку, работаю.
3. **Сохранение** расчётов под именем в каждой вкладке (файлы «распил» / «фасад» / «просчёт»).
4. **В «Просчёт мебели» добавить полные прайсы** ЛДСП и кромки **из калькулятора «Распил»**.
5. **Внести актуальные цены фасадов** из калькулятора «Фасады» в «Просчёт мебели».
6. **При печати в «Распил» добавить договор** — по образцу калькулятора «Фасады».
7. **Второй пароль для менеджера** (отдельный) + **водяной знак «среда»** (полупрозрачный, в углу).
8. **Водяной знак должен печататься** у менеджера (изначально был только на экране).
9. **Поиск декоров по названию** в «Просчёт мебели» (ввод части имени).

## 2. Результат (что сделано)

### Файлы
```
index.html    — вход по паролю (2 роли) + вкладки; точка входа
mebel.html    — «Просчёт мебели» (+ прайсы из Распила и Фасадов, + поиск декора)
fasad.html    — «Фасады» (+ водяной знак на печати)
raspil.html   — «Распил» (+ договор при печати, + водяной знак на печати)
README.md     — инструкция для пользователя (пароли, хостинг, сохранение)
HANDOFF.md    — этот документ
```

### Архитектура
- **`index.html` — оболочка.** Экран пароля, затем панель с тремя вкладками. Каждый
  калькулятор загружается в свой `<iframe>` (изоляция: отдельная область имён JS,
  свой DOM, свои ключи localStorage). Iframe грузится лениво при первом открытии
  вкладки и остаётся смонтированным — переключение вкладок не теряет введённые данные.
- **Изоляция хранилища:** ключи localStorage у калькуляторов не пересекаются
  (`mebelart_app_v2__*`, `sreda_calc_v1__*` / `sreda_prices_v3` / `sreda_recent_v1`,
  `svcCalcDocs_v1`), поэтому одновременная работа в одном браузере безопасна.
- **Защита прямого доступа:** каждый калькулятор при открытии напрямую (не во вкладке)
  уводит на `index.html`. Исключение — самостоятельные сохранённые копии
  (у mebel — заполненный `#appSeed`, у fasad — заполненный `#embedded-data`),
  они остаются автономными файлами.

### Ключевые доработки по целям
- **Прайсы в «Просчёт мебели» (цели 4–5).** В `mebel.html` массивы `EGGER_LDSP` и
  `EGGER_KROMKA` дополнены базой из «Распила» (`RASPIL_LDSP`, `RASPIL_KROMKA`; данные
  извлечены программно из `raspil.html`, не вручную). Итог: **406 декоров ЛДСП** —
  Egger (143) + Lamarty Р2/Р5, фанера, AGT, 5K и **АМК-Троя по названиям декоров**
  (~209 позиций: Дуб Сонома, Белый Снег и т.д., развёрнуты из `AMK_DECOR` по
  коллекции+группе). 9 групп кромки. Толщины в пикере берутся из прайса самого
  декора (было жёстко `[8,16,18,25]` — не показывало 10/22/6/9/12…). В `FACADE_CATALOG`
  добавлены «Покраска заказчика» (фреза/мыло/глянец), обратка приведена к прайсу
  «Фасады»: `FACADE_DOUBLE_SIDED_SURCHARGE = {paint:4500, veneer:5500}`.
- **Автосохранение в браузере (правка после отзыва).** `saveApp()` теперь всегда
  пишет состояние в `localStorage` (в т.ч. для встроенной копии «master»), а
  `loadApp()` восстанавливает его при повторном открытии — работа сохраняется
  автоматически. Файловое автосохранение (`showSaveFilePicker`) недоступно в
  cross-origin фрейме (локальное открытие как `file://`); теперь это определяется
  (`inCrossOriginFrame()`), кнопка честно сообщает «Автосохранение в браузере
  включено» вместо ошибки. На хостинге (один origin) файловое автосохранение
  доступно как дополнительная опция.
- **Договор в «Распил» (цель 6).** В `raspil.html` добавлены `buildContractHtml()` и
  `printContract()` по образцу «Фасады». Кнопка печати выдаёт два документа: смету,
  затем договор. Реквизиты ИП Малюга; сумма, ФИО и телефон — из расчёта; предмет —
  раскрой/кромление/присадка/пазование (со ссылкой на ГОСТ 16371-2014, допуск ±0,5 мм).
- **Две роли + водяной знак (цели 7–8).** В `index.html` два пароля:
  `OWNER_PASSWORD` и `MANAGER_PASSWORD`. Роль хранится в `sessionStorage`
  (`sreda3in1_role`). Менеджеру в src iframe добавляется метка `#mgr`; калькулятор по
  ней внедряет печатный водяной знак `.sreda-print-wm` (виден только в `@media print`),
  а в договоры дописывается такой же знак. Смена роли сбрасывает src вкладок, чтобы
  метка обновилась. Экранный водяной знак у менеджера тоже есть (в `index.html`).
- **Поиск декора (цель 9).** В `mebel.html` над списком ЛДСП — поле `.decor-search`
  с общим `<datalist id="ldspDecorList">` (все 406 декоров). Ввод части названия →
  подсказки → выбор проставляет декор, цену, толщину и синхронизирует выпадающий список.

### Пароли (текущие значения)
| Роль | Константа в `index.html` | Значение | Особенность |
|---|---|---|---|
| Владелец | `OWNER_PASSWORD` | `01010101` | Без водяного знака |
| Менеджер | `MANAGER_PASSWORD` | `2580` | Водяной знак «среда» (экран + печать) |

> Защита клиентская (проверка в браузере) — от случайных посетителей, не банковский уровень.

## 3. Обнаруженные проблемы и как решены

1. **Раскрой в iframe не инициализировался (PL undefined, 1 скрипт вместо 2).**
   Причина: `raspil.html` подключает Google Fonts через внешний `<link>`; при офлайн-
   тесте запрос висел и блокировал выполнение скриптов. В онлайне (у заказчика фонты
   грузятся) проблемы нет — подтвердил, закоротив запрос к фонтам в тесте. Файл
   не менялся (внешний шрифт был в исходнике). *Возможная доработка:* сделать `<link>`
   на шрифты неблокирующим или встроить шрифты для полной автономности.

2. **Headless-Chromium не стартовал** (`Old Headless mode has been removed`).
   Решение теста: запуск через `chromium_headless_shell` вместо основного бинарника.
   К продукту отношения не имеет.

3. **Проверка данных в песочнице Node:** `const` не попадает в объект контекста `vm`.
   Решение (только для теста): добавлял экспорт в `globalThis` в конце проверяемого среза.

4. **Экранирование кавычек в водяном знаке договора (Фасады).** Сначала внёс
   `font-family:Georgia,'Times New Roman',serif` в JS-строку с ошибочным экранированием —
   упростил до `font-family:Georgia,serif`, чтобы не было конфликта кавычек. Исправлено.

5. **Водяной знак не печатался (жалоба заказчика).** Причина: знак был в родительской
   странице `index.html`, а печать идёт из содержимого iframe. Решение — цель 8 выше
   (метка `#mgr` + внедрение печатного знака внутрь каждого калькулятора и в договоры).

Открытых дефектов на момент передачи нет.

## 4. Как проверялось

Прогоны в реальном Chromium (Playwright) — все PASS:
- **Оболочка/вкладки:** неверный пароль → ошибка; верный → вход; все три вкладки
  грузятся; в mebel 218 декоров ЛДСП, 9 групп кромки, 18 позиций фасадов.
- **Роли/водяной знак на экране:** владелец — без знака; менеджер — знак «среда»;
  роль и знак сохраняются при перезагрузке, сбрасываются по «Выйти».
- **Водяной знак на печати** (`@media print`): у менеджера `.sreda-print-wm`
  становится `display:block` во всех трёх калькуляторах; у владельца элемента нет.
- **Договоры:** в договорах «Распил» и «Фасады» знак есть у менеджера и отсутствует
  у владельца; договор содержит номер, ФИО, телефон, реквизиты ИП Малюга, сумму.
- **Поиск декора:** поле есть, datalist на 218 позиций; выбор по точному названию
  ставит декор/цену/толщину; частичный текст не меняет выбор (нужно выбрать подсказку).

Скрипты проверки — во временной папке сессии (в репозиторий не входят).

## 5. Хостинг и сохранение

- **Хостинг:** статический сайт из 4 файлов. Включить GitHub Pages
  (Settings → Pages → ветка) или залить файлы в одну папку на любой статический хостинг.
  Открывается и локально (двойным щелчком), но онлайн удобнее для доступа с разных ПК.
- **Сохранение расчётов:** в памяти браузера конкретного ПК + выгрузка файла/PDF/Excel
  в каждой вкладке. Список сохранённых виден только на том ПК/браузере, где создан;
  перенос — через выгруженный файл.

- Поле «Адрес заказчика» в договоре «Распил» (сейчас прочерк — в калькуляторе нет
  такого поля).

## 7. История коммитов (ветка `claude/magical-noether-9ekvhi`)
